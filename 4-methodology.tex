\section{แนวคิดของงานวิจัยและวิธีการดำเนินงาน}
\label{sec:method}

\subsection{แนวคิดของงานวิจัย}

% แนวคิดหลักของงานวิจัยนี้คือการแยกการควบคุมบทสนทนาออกจากการตีความคำตอบ ส่วนควบคุมบทสนทนาทำงานแบบกำหนดแน่นอนตามแบบประเมิน
% เพื่อให้ผู้ป่วยทุกคนได้รับคำถามที่มีถ้อยคำเหมือนกันและตรงตามต้นฉบับ ขณะที่แบบจำลองภาษาทำหน้าที่เฉพาะการจับคู่คำตอบภาษาพูดของผู้ป่วยเข้ากับระดับคะแนนของข้อคำถาม
% ระบบที่นำเสนอประกอบด้วย 6 องค์ประกอบ ดังรูปที่~\ref{fig:system-arch} และทุกองค์ประกอบทำงานบนเซิร์ฟเวอร์ภายในโรงพยาบาล
% โดยไม่มีการส่งข้อมูลเสียงหรือข้อความของผู้ป่วยไปยังบริการภายนอก

แนวคิดหลักของงานวิจัยนี้คือการใช้ส่วนควบคุมบทสนทนาแบบ finite-state machine ในการควบคุมการสนทนากับผู้ป่วยตามแบบประเมินที่กำหนดไว้ล่วงหน้า 
โดยให้ผู้ป่วยตอบคำถามทีละข้อผ่านเสียงพูด และใช้ LLMs ในการตีความคำตอบของผู้ป่วยเพื่อจับคู่กับตัวเลือกที่กำหนดไว้ในแบบประเมิน 
หลังจากผู้ป่วยตอบคำถามครบทุกข้อ ระบบจะคำนวณคะแนนรวมตามสูตรคำนวณของแบบประเมินที่ใช้และแสดงผลลัพธ์ให้ผู้ป่วยทราบ
ซึ่งระบบที่นำเสนอประกอบด้วย 6 ส่วน ดังรูปที่~\ref{fig:system-arch} และทุกองค์ประกอบทำงานบนเซิร์ฟเวอร์ภายในโรงพยาบาล
โดยไม่มีการส่งข้อมูลเสียงหรือข้อความของผู้ป่วยไปยังบริการภายนอก

\centering
\includegraphics[width=0.55\textwidth]{figures/system_architecture.png}
\caption{สถาปัตยกรรมของระบบที่นำเสนอ}
\label{fig:system-arch}
\end{figure}

\begin{enumerate}
    \item \textbf{ePRO Form (JSON Format)}: คือ ePRO ที่ถูกแปลงให้อยู่ในรูปแบบ JSON เรียบร้อยแล้ว ซึ่งโครงสร้างจะประกอบด้วยข้อคำถาม 
    ระดับคำตอบเชิงอันดับพร้อมคำบรรยาย ไฟล์เสียงและภาพประกอบของแต่ละข้อ และประเภทของแบบประเมิน (DASH หรือ TESS)
    เพื่อให้สามารถนำไปงานต่อไปอย่างสะดวกและทำให้เพิ่มแบบประเมินใหม่ได้โดยไม่ต้องแก้ไขโปรแกรม
    \item \textbf{Dialogue Manager}: ควบคุมบทสนทนาแบบ finite-state machine 
    ที่จะเป็นตัวกำหนดลำดับการถามคำถาม และรับผลค่าความมั่นใจจาก option extractor 
    หากค่าความมั่นใจของการจับคู่สูงกว่าเกณฑ์ ระบบจะบันทึกตัวเลือกและไปยังข้อถัดไป
    หากต่ำกว่าเกณฑ์ ระบบจะเล่นเสียงขอให้ตอบใหม่หรือเสียงอ่านตัวเลือกที่สร้างไว้ล่วงหน้า
    และเมื่อถามซ้ำครบจำนวนครั้งที่กำหนดแล้วยังไม่ได้คำตอบที่ชัดเจน จะบันทึกข้อนั้นไว้ให้พยาบาลตรวจสอบ
    \item \textbf{Question Presenter}: เล่นเสียงคำถามที่ถูกสังเคราะห์ด้วย OmniVoice \citep{Zhu2026OmniVoice} และตรวจสอบไว้ล่วงหน้าแล้วพร้อมแสดงภาพประกอบ เพื่อให้ถ้อยคำคงที่และช่วยให้ผู้ป่วยเข้าใจคำถาม
    \item \textbf{Speech Recognizer}: บันทึกเสียงคำตอบของผู้ป่วยทีละข้อ แล้วแปลงเป็นข้อความด้วยแบบจำลอง Typhoon Whisper Turbo 
    จากนั้นส่งข้อความไปยัง option extractor เพื่อจับคู่กับตัวเลือกของข้อคำถาม
    \item \textbf{Option Extractor}: ทำการจับคู่ข้อความคำตอบเข้ากับระดับคะแนนของข้อคำถามด้วย Qwen3.5 ซึ่งทำหน้าที่เป็นแบบจำลองตัดสินใจ
    โดยไม่สร้างข้อความตอบกลับ แต่ให้ผลลัพธ์เป็นการแจกแจงความน่าจะเป็นของทุกตัวเลือกรวมผลลัพธ์พิเศษจากค่า logit ของโทเค็นที่แทนรหัสของตัวเลือก
    ผลลัพธ์ที่ส่งให้ dialogue manager ประกอบด้วยตัวเลือกที่มีความน่าจะเป็นสูงสุดและค่าความมั่นใจ
    โดยเกณฑ์ค่าความมั่นใจกำหนดจากชุดข้อมูลสำหรับปรับค่า
    \item \textbf{Score Calculator}: ทำการแปลงตัวเลือกรายข้อเป็นคะแนนและคำนวณคะแนนรวมตามสูตรของแบบประเมินแต่ละฉบับด้วยโปรแกรม
    เพื่อให้การคิดคะแนนเป็นไปตามแบบประเมินต้นฉบับและทำสามารถทำซ้ำได้
\end{enumerate}

\subsection{วิธีการดำเนินงาน}

\begin{enumerate}
    \item ศึกษาทฤษฎีและงานวิจัยที่เกี่ยวข้องกับ PROMs ตัวแทนสนทนาในทางการแพทย์ การรู้จำเสียงพูดภาษาไทย และการตีความคำตอบด้วยแบบจำลองภาษา
    \item จัดทำแบบประเมิน DASH และ TESS ในรูปแบบโครงสร้างข้อมูล JSON และจัดทำเสียงคำถาม เสียงขอให้ตอบใหม่ เสียงอ่านตัวเลือก และภาพประกอบ
    \item ออกแบบและพัฒนา dialogue manager แบบ finite-state machine และเชื่อมต่อกับ question presenter และ speech recognizer
    \item จัดทำชุดข้อมูลคำตอบสังเคราะห์ภาษาไทย และแบ่งเป็นชุดสำหรับปรับค่าและชุดทดสอบ
    \item พัฒนา option extractor ด้วย Qwen3.5 กำหนดเกณฑ์ค่าความมั่นใจ และประเมินประสิทธิภาพ
    \item ทดลองใช้ระบบกับผู้ป่วยจริงควบคู่กับการสัมภาษณ์โดยพยาบาล
    \item วิเคราะห์ผล สรุปผลการวิจัย และจัดทำวิทยานิพนธ์
\end{enumerate}

\subsection{การทดลองและการประเมินผล}

\subsubsection{การทดลองที่ 1: การประเมิน Option Extractor}

ทดสอบ option extractor กับชุดทดสอบของชุดข้อมูลคำตอบสังเคราะห์ โดยเปรียบเทียบ Qwen3.5 ขนาดต่าง ๆ ที่ทำงานได้บนเซิร์ฟเวอร์ภายใน
เพื่อเลือกขนาดที่เหมาะสมระหว่างความถูกต้องกับทรัพยากรการคำนวณ และวัดผล 2 ด้าน ดังนี้
\begin{enumerate}
    \item \textbf{ความถูกต้องของการจับคู่} วัดด้วยความถูกต้อง (accuracy) ค่า Macro-F1 และค่าสัมประสิทธิ์แคปปาแบบถ่วงน้ำหนัก (weighted kappa) \citep{Cohen1968}
    ซึ่งคำนึงถึงระยะห่างระหว่างระดับคะแนนที่ทำนายผิด
    \item \textbf{ความน่าเชื่อถือของค่าความมั่นใจ} วัดด้วยค่าความคลาดเคลื่อนของการปรับเทียบที่คาดหวัง (Expected Calibration Error: ECE)
    ซึ่งวัดความแตกต่างระหว่างค่าความมั่นใจกับความถูกต้องจริง \citep{Guo2017} และวัดความถูกต้องของคำตอบที่ระบบยอมรับ
    เทียบกับสัดส่วนของคำตอบที่ต้องถามซ้ำ ที่เกณฑ์ค่าความมั่นใจระดับต่าง ๆ
\end{enumerate}
ผลการทดลองนี้ใช้เลือกขนาดของแบบจำลองและเกณฑ์ค่าความมั่นใจที่ใช้ในการทดลองที่ 2

\subsubsection{การทดลองที่ 2: ความสอดคล้องกับการสัมภาษณ์โดยพยาบาล}

ผู้ป่วยแต่ละรายตอบแบบประเมินทั้งผ่านระบบและผ่านการสัมภาษณ์โดยพยาบาล จากนั้นวัดความสอดคล้องในระดับรายข้อด้วยค่าสัมประสิทธิ์แคปปาแบบถ่วงน้ำหนัก \citep{Cohen1968}
และในระดับคะแนนรวมด้วยค่า ICC \citep{Koo2016}
% TODO: ลำดับการตอบ (สลับลำดับระหว่างระบบกับพยาบาล) ระยะห่างระหว่างสองครั้ง และจำนวนผู้ป่วย
นอกจากนี้ ถอดเสียงคำตอบด้วยมือสำหรับคำตอบส่วนหนึ่ง เพื่อวัดค่า CER ของ speech recognizer
และเปรียบเทียบผลการตีความคำตอบบนข้อความจาก speech recognizer กับข้อความที่ถอดด้วยมือ
ซึ่งแยกผลกระทบของความผิดพลาดจากการรู้จำเสียงพูดออกจากความผิดพลาดของ option extractor
ตัวชี้วัดรองประกอบด้วยอัตราการตอบแบบประเมินครบ สัดส่วนของข้อที่ต้องถามซ้ำ สัดส่วนของข้อที่ส่งให้พยาบาลตรวจสอบ และเวลาที่ใช้ต่อการประเมินหนึ่งครั้ง
